# Evidence guide

For each of `dayjs`, `yt-dlp`, and `caddy`:

- `*-raw-output.md`: complete original human-readable Factory response, also embedded in the write-up.
- `*-report.json`: original report-tool input, including all 84 criterion scores and rationales and the evaluated commit.
- `*-receipt.json`: successful Factory storage response and report ID.
- `*-github.json`: saved public repository metadata used for repository creation dates and ownership context.

Shared evidence:

- `repo-manifest.json`: exact commits, default-branch commit dates, tracked-file counts, and primary-extension physical-line counts. Counts include tests/comments/blanks and tracked generated files. They are not production SLOC.
- `run-record.json`: CLI version/checksum, model, sessions, successful storage, final clean repository status, and audit limitations.
- `criterion-levels.json`: criterion IDs, level annotations and skip eligibility extracted from the actual CLI audit specification. Its level annotations do not replace the installed CLI's global-rate maturity calculation.
- `comparison.json`: complete course/native group mappings, per-repo and pooled calculations, common-evaluated-criteria comparisons, and a symmetric six-criterion observer/history sensitivity check with exclusion reasons.
- `sensitivity-table.md`: all four comparison bases, including the 51 common criteria remaining after observer/history exclusions. These are analyst calculations, not revised official Factory scores or levels.
- `*-pillar-table.md` and `failures-table.md`: deterministic tables regenerated by `python3 week5/recompute.py` from the assignment-repository root.
- `checksums.json`: SHA-256 hashes of the other evidence files at final validation; excludes itself.

No authentication file, API key, encrypted model reasoning, or unrelated session context is included. The three JSON payloads and raw responses retain Factory's judgments, including context-sensitive or questionable scores discussed in the write-up. Proposed fixes were not implemented, and full upstream test suites were not run.

The native group membership was checked against Caddy's stored Factory dashboard on November 1, 2026. Mission Readiness is an overlapping subset view, not an additional independent pillar. Course grouping separates Code Quality and retains all new criteria in two supplemental groups, so every criterion is counted exactly once in either mapping.

The local revision preserves the three original reports and receipts. It clarifies the sample-design tradeoff, corrects the age interpretation, replaces the unsupported container-first priority for yt-dlp with an existing-CI feedback proposal, and adds sensitivity calculations. It does not supply new successful runtime tests or additional Git history.
